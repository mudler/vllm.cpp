## Isolated hypothesis

Pinned vLLM uses exact eight-token programs and `BLOCK_N=256` at
`${VLLM_SOURCE}/vllm/model_executor/layers/mamba/ops/causal_conv1d.py:15-79`
and `:689-744`. Its traced launch is grid feature extent 32, block 128 and 32
registers/thread: Triton maps 256 feature elements across four warps.

The local K=4 arm 1 at `src/vt/cuda/cuda_gdn.cu:793-960` owns one channel per
thread, so block 128 requires 64 feature blocks. The rejected arm 2 halves that
grid with two channels per thread, but duplicates weights/windows, raises the
trace-visible register count 52→58 and is 4.052% slower than arm 1.

This discriminator instead gives **one channel to each of 256 threads**. It
also produces 32 feature blocks, but does not duplicate any lane's weights,
window, bias or state pointers. Relative to two arm-1 blocks, it keeps the same
total 256 threads/eight warps and channel-local arithmetic while halving
block-level descriptor and sequence/chunk control. It is deliberately a
single-variable test of block width, not a claim that CUDA's lane mapping is
identical to Triton's vectorized four-warp program.

The counter-hypothesis is explicit: 52 registers × 256 threads consumes roughly
twice the registers per block, and the larger block may reduce residency enough
to erase the saved control. Nsight Compute is unavailable, so occupancy is not
asserted; the per-shape timing and CUPTI launch metadata decide the experiment.

## Port and rollback

Extend the existing same-binary selector with exact arm `3`:

- `0`: runtime-width, block 128, one channel/thread;
- `1`: K=4, block 128, one channel/thread (current winner/control);
- `2`: K=4, block 128, two channels/thread (retained falsified control);
- `3`: K=4, block 256, one channel/thread (this discriminator).

Unset and invalid spellings remain arm 0. Non-K4 and non-positive channel shapes
fall back to arm 0. Generalize the K4 kernel/launcher by compile-time block
threads and channels-per-thread so arms 1 and 2 instantiate their existing
128-thread contracts and arm 3 instantiates `<256,1>`. Channel indexing and
feature-block calculation must use the selected compile-time block width; no
metadata, state layout, tensor stride, scheduler, model, post-conv or default
path changes are in scope.

Every active channel must retain exactly the shipped order: bias; K=4 taps in
ascending order; optional SiLU; output store; window shift; raw-input final-state
writeback. The arm stays opt-in even if locally positive because the repeated
local and hardware-unavailable 27B/35B default gates remain open.

## Red tests and gates

Before implementation, extend the portable contract so it fails to compile or
fails assertions until arm 3 exists. It must prove:

1. only exact string `"3"` selects the new arm; `"30"`, `"3garbage"`, empty,
   unset and all other values preserve arm 0;
2. C=8192,K=4 resolves arm 3 to 32 feature blocks and 256 threads; partial
   channels round up; unsupported widths resolve to arm 0/64/128;
3. the shared production dispatcher invokes the arm-3 callback exactly once;
   deleting the callback branch or mapping it to arm 1 is RED;
4. CUDA arm 3 is byte-identical to arm 1 for output and final state over the
   existing BF16/F32, initial/fresh state, unequal exact chunks, `T<K-1`,
   partial-channel and padded-row matrix; a block-width/index mutation is RED.

Focused green gates are `test_gdn_prefill_conv`, `test_ops_gdn`, and
`test_qwen35_paged_forward`, followed by staged/full preflight. The production
token file must remain byte-identical to the baseline SHA above.

## Performance acceptance and stop conditions

Profile arms 1 and 3 from the same rebuilt binary, under one GPU lease/lock and
the same cgroup/workload. Arm 3 is retained only if it improves the combined
279/280-program 912-call total by at least 1% and does not regress total
causal-conv time. A retained arm then owes an enclosing profile with
total/output throughput, TTFT, TPOT/ITL, E2E and peak VRAM all non-regressing.

If arm 3 misses either micro bar, revert its product/test code and append the
refutation to the benchmark record/spec; do not leave another dormant selector.
If it passes, keep it opt-in, record the exact trace/hash/ratios in the keyed and
append-only checkpoint surfaces, then select the next trace-local residual.
Any correctness mismatch stops performance work immediately.

## Measured result and disposition

The operator rebuilt one production binary at `84c7e23b0` and profiled arms 1
and 3 in one GPU lease, `/tmp/gpu` lock and 22/25 GiB cgroup with the workload
above. Both token files have SHA-256
`83fcdc45f79ddb06a634c7d7d95eba3384543b3cd781a45a8db1fc4e2a453545`,
so correctness held. The selected 279+280 programs were 127.645906 ms over 912
calls for arm 1 and 142.936163 ms for arm 3: arm 3 was **11.9802% slower**.
All causal-conv shapes were 219.400955 ms versus 245.421363 ms, an **11.8598%
regression**. CUPTI confirmed the intended structural change from grid-x 64,
block 128, 52 registers/thread to grid-x 32, block 256, 52 registers/thread.

The enclosing single profiles also moved the wrong way: total/output throughput
6772.76/748.91 to 6756.52/747.12 tok/s, TTFT 1014.42 to 1016.46 ms,
TPOT/ITL 34.84 to 34.93 ms and E2E 5439.06 to 5452.21 ms. The 256-thread
block therefore fails both micro acceptance bars and the enclosing check. Its
product and test selector are removed as required; exact string `"3"` again
falls back to arm 0, while shipped arms 0/1/2 are unchanged.
