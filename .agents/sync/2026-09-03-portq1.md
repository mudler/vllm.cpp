### 2.2 The labels

`ALREADY_SATISFIED` cites the `file:line` or symbol that satisfies the entry.
`REAL_GAP` says what is missing, roughly how big, and who owns it.
`NOT_APPLICABLE` splits, because the two halves have different futures:

- **`surface-absent`** — the commit edits something this tree does not carry.
  Discarded work; there is nothing to port until the underlying feature is.
- **`inert:<gate>`** — the surface is here and the new arm is gated on something
  unreachable in every configuration this tree builds. **Deferred** work: it
  becomes real the day that gate is ported, so the gate is named.

## 6. One thing that is not a gap and is still a finding

### 6.1 A prior triage of `[31]` reached the opposite conclusion, and it is stale

`b7e414cc4` skipped vllm#48245 with a reason: "async_tokens_to_discard is never
set; no PP batch-queue window — **so the underflow cannot occur**". This wave and
[#2531](https://github.com/mudler/vllm.cpp/issues/2531) call it a live defect.
Both cannot stand, and the old note is the one that falls.

**Its premise still holds.** `async_tokens_to_discard` is initialised to 0
(`include/vllm/v1/request.h:271`), decremented under a `> 0` guard that therefore
never fires (`src/vllm/v1/core/sched/async_scheduler.cpp:80-81`) and read at
`src/vllm/v1/core/sched/scheduler.cpp:1215`. Nothing assigns it a positive value.

**Its conclusion does not follow, because the underflow does not run through that
field.** The path is: async scheduling active, then a preemption. `preempt_request`
zeroes `num_computed_tokens` and never touches `num_output_placeholders`
(`src/vllm/v1/core/sched/scheduler.cpp:345-371`), and
`src/vllm/v1/core/sched/async_scheduler.cpp:94` then decrements it
unconditionally, guarded only by an `assert` on the next line. Neither step reads
`async_tokens_to_discard`.

**And the reachability moved under the note.** `include/vllm/config/scheduler.h:176`
resolves the default `async_scheduling` (`std::nullopt`) to **ON when
compatible**, so the arm the 2026-07-30 note treated as unreachable machinery is
the default one today.

This is recorded so the stale note stops misleading the next reader of
`git log --grep 48245`. It is not a criticism of the triage, which was accurate
when written; it is what a carried disposition looks like after the tree moves.
