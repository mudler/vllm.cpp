one was off by four lines (§6.11). Re-reading an anchor confirms the line is
there; it cannot detect that the line supports the opposite conclusion. That is
the same structural hole §2.3 names for claims of absence, in a new place: **a
citation re-read verifies existence, never inference.**

**The rule this yields, for the tranches that follow.** For a multi-file commit,
enumerate the files it touches and give each a label, before matching any symbol.
Where a tree file's own header names an upstream file, that naming is the
authority on which kernel is ported — read it before deciding the surface is
absent. And a sentence of the form "the optimization is already present because
`<anchor>`" must cite the **post**-commit shape; if the anchor matches the
pre-commit shape, the sentence is inverted.

## 10. What this implies for the rest — an extrapolation, not a count

**11 of 40 is 27.5%.** The four tranches now read 15%, 22.5%, 20%, 27.5%;

Applied to the 290: **roughly 58-68 real gaps. This is an estimate derived from
four contiguous tranches plus one stratified sample, totalling 223 entries. It is
not a count of anything.**

**Five reasons not to treat 27.5% as the rate**, stated inline because the number
will be quoted:

1. This is a contiguous slice of commit history, not a random draw, so a period
   effect and a sample rate are not separable here.
2. **Two of this tranche's eleven are pre-pin holes that the commit range cannot
   see** (`[129]`, `[156]`), and one is a re-finding of an already-filed gap
   (`[133]`). Counted as "gaps this commit range introduces", the honest figure
   is **8 of 40**, or 20% — squarely on the earlier tranches' rate. **The 27.5%
   is real work owed; it is not evidence that the rate rose.**
3. Shape D is growing, not the gap rate: 0, then some, then 2, now 8. A queue
   derived from a commit range structurally cannot see a pre-pin hole, so the
   later tranches are finding more of what the queue was never able to represent.
4. Eleven of forty is small enough that two entries landing either way moves the
   figure from 22.5% to 32.5% — and `[132]` moving is exactly what happened.
5. The four tranches cluster by subsystem differently. This one's gaps are spread
   across scheduling, structured output, sampling, KV specs, cudagraphs and a MoE

**What is a count, and holds regardless:** these forty contain eleven real gaps
