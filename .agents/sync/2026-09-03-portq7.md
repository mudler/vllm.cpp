### 4.2 Three of the ten are worse than a missing forward-port

- **`[283]` is an unclamped write index reachable from an unauthenticated
  request.** Every link was re-read by the operator across six files. What makes
  it more than a validation gap is that nothing downstream clamps: `ApplyTokenMask`
  checks shape and dtype, and both the CPU and CUDA kernels index
  `logits[row * v + cols[k]]` raw. A negative id underflows the same expression.
  **The tree has already paid for this shape once** and says so in a comment at
  `input_processor.cpp:137-141`: a single `{"logprobs": 999999}` "killed the
  server process" (#249). Nothing was run here, so whether a given `v` and id
  place the write inside the same allocation is undetermined; the guard is
  warranted either way.
- **`[266]` corrupts a counter before it throws.** Upstream's Python returned an
  empty list for a negative count. Here the negative passes `get_new_blocks`'
  bound check, skips `popleft_n`'s zero guard, decrements `num_free_blocks` **by
  a negative** — inflating the pool's own idea of how many blocks are free, the
  exact corruption upstream's new regression test asserts against — and only then
  throws from `reserve`. The `assert` on the path is compiled out under `NDEBUG`.
  Live reachability through `allocate_slots` is **undetermined** and the issue
  says so; the clamp is one line.
- **`[254]` requires reversing a committed decision, not just adding code.**
  `.agents/specs/tool-call-history-arguments.md` states fail-closed four times and
  a test pins the throw. Upstream has converged on the opposite with a stated
  reason this project did not have: a malformed argument lives in conversation
  **history**, so failing on it fails every later turn. A fresh reviewer must be
  told the test inversion is the assertion changing sides, not an assertion being
  deleted.

green while reporting nothing.

It is recorded rather than quietly fixed for one reason: **a records-only wave is
exactly the shape that makes the role gate feel optional**, because nothing is
compiled and nothing is measured, so the discipline that gate enforces looks like
paperwork until a checker asks. Five tranches preceded this one; whether any of
them declared a role is not visible from their records, and this note exists so
the sixth does not have to wonder.

**Preflight also prints `NOT a green preflight` for a structural reason, and that
is not a finding about this change.** Five gates SKIP because preflight does not
supply the arguments they need — `check-arm-isa-build.py`, `check-cpu-isa-build.py`,
`check-cuda-fat-gencode.py`, `check-triton-aot-multiarch.py` and
`check-pr-size.py`. Three need a compile-commands database, and preflight itself
reports that "no translation unit is in scope: nothing this change touches is a
C++ source, a header or a build file". `check-pr-size.py` is the one of the five
that is meaningful for a records-only change, so it was run explicitly, above.

**The verdict was read the prescribed way, and the prescription itself needs
narrowing.** The log was ANSI-stripped, checked for its terminal summary block
**first**, and only then grepped for `gate(s) failed` and `NOT a green`. The
mid-run polls in this session were deliberately treated as "still running" rather
than as clean, because a log that has not reached its summary answers 0 to both
greps for the same reason an unmatched grep does.

But "never trust the exit code" is too broad, and the sharper rule matters
because a sibling review found the broad version being justified by a claim that
is false. **A failure is reliably in the exit status; a SKIP is not.**
`scripts/agent-preflight.sh:724-728` prints `N gate(s) failed` and then
`exit 1` **unconditionally** — there is no path on which preflight reports a
failed gate and exits 0. The skip block above it at `:717-723` prints
`NOT a green preflight` and falls through to exit 0 unless `--fail-on-skip` is
passed, and the comment at `:730-734` says why in as many words: a caller
"reads the STATUS and not the report, which is what agent-ready.py did while
printing the word 'green' over two gates that never ran."

So an exit 0 from preflight means "nothing failed", **not** "everything ran", and
that is the whole content of the rule. Any observation of a non-zero report
beside a zero status is `$?` reading the wrong end of a pipe — an ANSI-strip
pipeline makes `$?` the rc of `sed`, not of preflight — which is why every rc in
the table above was captured with a redirect and read on the next line rather
than through a pipe.
