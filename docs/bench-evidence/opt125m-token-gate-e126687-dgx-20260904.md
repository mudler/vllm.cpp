## What this is, and what it is not

**This is the OPT-125m oracle gate.** It establishes one thing: that the pinned
oracle at `e126687a9a` produces the committed golden on GB10. It says **nothing
about `qwen4_exp` token identity**, nothing about any other model, and nothing
about our own arm at today's HEAD. `facebook/opt-125m` at six prompts and
sixteen tokens is the smallest declared token gate this tree has, and
`.agents/oracles/vllm.md` blocker 2 names it as such.

**No speed, latency or memory axis becomes admissible from this.** A passing
correctness gate is a precondition for quoting a performance result, never a
performance result. The benchmark baselines in `docs/benchmarks/` are still
measured at `555967922` and still owe step 6
([#2818](https://github.com/mudler/vllm.cpp/issues/2818)).

**Our arm was not re-run.** The byte-identity above means the existing green
`tests/vllm/models/test_opt_paged_engine` measurement carries over to *these
bytes* unchanged, because they are the same bytes. It does not mean our arm was
re-run at today's HEAD; that is a separate lease.

**The other four strict goldens are untouched** — 27B W4A4, 32B-NVFP4A16, 35B,
Coder. The `555967922` advance re-captured all four; none has been re-captured
at `e126687a9a`.

## A runtime wrapper stood between `rc` and the harness, and a later reader must know it

The job `rc` invoked was **not** `job.sh` directly. It was
`/workspace/tokengate-e126687/requeue-prebuild.sh`, a runtime wrapper on the
share, which `exec`'d `job.sh` unmodified. This is recorded here rather than
elided because "what ran" has to be answerable from the record alone.

**Why it existed.** `job.sh` builds with `pip wheel --no-build-isolation`, and
that flag makes pip skip `pyproject.toml`'s `[build-system] requires` entirely.
`job.sh`'s hand-written pre-install named six packages where the pin's
`[build-system] requires` names nine — `cmake`, `ninja`, `packaging`,
`setuptools`, `setuptools-scm`, `setuptools-rust`, `torch`, `wheel`, `jinja2`,
read from `pyproject.toml` at `e126687a9a` in the staged bundle. That is exactly
what killed `efc30c74` at exit 4.

**The wrapper installed FIVE packages, not three.** Its one install is
`requeue-prebuild.sh` line 54, read from the retired copy on the share:

```
"$W/venv/bin/pip" install -q -U "packaging>=24.2" "setuptools-rust>=1.9.0" "jinja2>=3.1.6" regex build
```

Three of those are the missing PEP-518 build requires. `regex` and `build` are in
no `[build-system] requires` at this pin, and neither is what `efc30c74` failed
on — that was `setuptools_rust`. This is recorded rather than elided because
"what ran" has to be answerable from the record, and because a wrapper that
installs more than it says is how an environment difference stops being visible.
Nothing else in the wrapper touches the build: it installed into the venv
`job.sh` then reused, and handed off with `exec`.

**What it did not do.** It changed nothing about the measurement. Verified here
by hash rather than by its own claim: the share's `job.sh` is
`bf77dfbb3383d837d2c00d738128de453915f8e59c28f9db27308de769b4857a`, which is
byte-identical to the committed `.agents/scripts/tokengate-e126687-job.sh` **at
`17fcdd5e3^`**, the parent of the build-requires repair. It is *not* identical to
that file on `main` today (`7aa702e065…`), because
[#2905](https://github.com/mudler/vllm.cpp/pull/2905) repaired the committed
harness after this run — `job.sh` now installs
`requirements/build/cuda.txt` from the clone at `$TARGET_SHA`, so the list cannot
drift from the pin, and asserts the outcome by parsing `[build-system] requires`
out of the cloned `pyproject.toml`.

The wrapper's own preamble is in the log:

```
### WRAPPER requeue of efc30c74-005e-4e80-bc28-bd34f5b76b77 (exit 4: no module setuptools_rust)
### WRAPPER setuptools_rust 1.13.0
### WRAPPER cargo=ABSENT  rustc=ABSENT
### WRAPPER handing off to job.sh (exec: the exit code below is job.sh's)
```

**The wrapper is retired, not deleted.** It is on the share as
`requeue-prebuild.sh.superseded-by-pr2905` beside a `README-requeue-prebuild.txt`
that says why it must not be resurrected: "it hardcodes three package names that
cannot follow the pin", so it would now shadow a fix that is better than it.
**That README undercounts in the same way this file did** — the wrapper's one
`pip install` names five — and it is on the share, outside this repository, so
this sentence records the discrepancy rather than silently correcting a file no
pull request can reach. The reason it gives is unaffected: a hardcoded list
cannot follow the pin whether it holds three names or five.
Queue `.agents/scripts/tokengate-e126687-job.sh` directly. It is kept renamed so
the provenance of this job stays readable.
