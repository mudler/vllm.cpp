  $ ps -o pid,ppid -p 2461973 -p 3290639   -> both PPID 1, both alive

`rc logs` on a QUEUED job exits 0 and prints NOTHING, because the job has
produced no output yet. Zero bytes is not `not_found`, and an empty `out/`
directory is the expected state of a job that has not started. Both signals
are indistinguishable from a cancelled job if the job's STATE is not read.

THE LESSON, and it is the repository's own: an absence is not a verdict. Read
the state the controller reports (`rc ps` / `rc jobs`), never the emptiness of
a log. This is `never-assert-absence-from-a-failed-grep` wearing rc's clothes.
